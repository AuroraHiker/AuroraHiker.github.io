# 1. 程序设计的基本结构

所有任务都可以解构为以下 **顺序、条件、循环** 三种基本结构。无论多么复杂的程序，归根结底都是由这三种结构组合而成的。下面我们逐一来看 Python 如何实现它们。

## 1.1 顺序结构

顺序结构就是代码**从上往下逐行执行**，没有跳转。这是所有程序的默认执行方式，也是另外两种结构 (条件和循环) 的“地基”——即使有分支和循环，代码的整体走向依然是顺序的，只是局部发生了跳转。

```python
print("第一步")
print("第二步")   # 先执行完上一行，才执行这一行
print("第三步")
```

## 1.2 条件结构 (if / elif / else)

根据条件是否成立，决定执行哪段代码。语法上注意 **冒号** 和 **缩进** (缩进后面会专门讲)。

```python
age = 18
if age >= 18:
    print("已成年")
else:
    print("未成年")
```

多分支用 `elif`：

```python
score = 85
if score >= 90:
    print("优秀")
elif score >= 60:
    print("及格")
else:
    print("不及格")
```

> 在条件结构中，Python 会从**上到下依次判断**每个条件，一旦某个条件成立，就会执行对应的代码块，并跳过后面所有的 elif 和 else。注意，else 不需要写任何条件，它表示所有条件都不满足时的默认情况。

## 1.3 循环结构 (for / while)

重复执行某段代码，直到条件不满足。

- **`for` 循环**：常用于遍历序列 (如列表、字符串) 或固定次数。

```python
# 遍历列表
for fruit in ["苹果", "香蕉", "橘子"]:
    print(fruit)

# 重复 5 次 (range(5) 生成 0~4) 
for i in range(5):
    print(f"第 {i} 次循环")
```

- **`while` 循环**：只要条件为真就继续，适合不知道具体次数的情况。

```python
count = 0
while count < 3:
    print("循环中...")
    count += 1   # 一定要修改条件，否则死循环
```

> 使用 `while` 时，务必记得在循环体内改变循环变量的值，否则会陷入死循环。

## 1.4 三元操作与列表推导式 (进阶)

### 1.4.1 三元操作 (if-else 简写)

三元操作是一种 **简写的 if-else**，适合在单行内根据条件赋不同值。

```python
age = 20
status = "成年" if age >= 18 else "未成年"
print(status)   # 输出：成年
```

语法：`值1 if 条件 else 值2` —— 条件成立取 `值1`，否则取 `值2`。


### 列表推导式 (循环 + 条件的组合简写)

三元操作不只用于单个值的判断，它还可以和循环结合，在**一行代码内**对列表中的所有元素进行批量处理。这种写法被称为 **列表推导式**。

举个场景：你有一个数字列表，想把所有偶数保留下来，过滤掉奇数。

传统的写法需要先用 `for` 循环遍历，再用 `if` 判断，最后用 `append` 添加到新列表，至少需要三四行代码。而用列表推导式可以压缩成一行：

```python
# 传统写法
numbers = [1, 2, 3, 4, 5, 6]
result = []
for n in numbers:
    if n % 2 == 0:
        result.append(n)
print(result)   # 输出：[2, 4, 6]

# 列表推导式写法 (一行搞定)
numbers = [1, 2, 3, 4, 5, 6]
result = [n for n in numbers if n % 2 == 0]
print(result)   # 输出：[2, 4, 6]
```

列表推导式还能结合三元操作，在遍历的同时根据条件决定每个元素取什么值。比如把列表中的奇数变成 `"奇数"`，偶数变成 `"偶数"`：

```python
numbers = [1, 2, 3, 4, 5]
result = ["偶数" if n % 2 == 0 else "奇数" for n in numbers]
print(result)   # 输出：['奇数', '偶数', '奇数', '偶数', '奇数']
```

格式拆解：`[对每个元素做的事 for 元素 in 列表 if 筛选条件]`

顺序是**先循环、再判断、最后取结果**，读的时候可以从 `for` 开始往两边读。


**新手须知**：三元操作和列表推导式属于“进阶语法”，它们存在的意义是让代码更简洁、更高效——尤其是在处理大量数据时，列表推导式比手动 `for` 循环速度更快，因为它在底层经过了优化。但如果你是初学者，暂时不学它们也完全不影响你写程序。先用 `if-else` 和 `for` 循环把逻辑理清楚，等你写习惯了，自然会觉得这些简写用起来更顺手。到时候再回来翻这一节也来得及。

# 2. Python 的基础运算

## 2.1 数学运算符

| 运算符 | 含义       | 示例       |
|--------|------------|------------|
| `+`    | 加         | `3 + 5`    |
| `-`    | 减         | `10 - 4`   |
| `*`    | 乘         | `2 * 6`    |
| `/`    | 除 (浮点)  | `10 / 3` → 3.333... |
| `//`   | 整除 (取整) | `10 // 3` → 3 |
| `%`    | 取余 (模)  | `10 % 3` → 1 |
| `**`   | 幂运算     | `2 ** 3` → 8 |

**需要注意以下几点：**

- 加减乘 (+ - *) ：只要参与运算的任意一方是浮点数，结果就是浮点数。比如 3 + 2.0 得 5.0，4 * 1.5 得 6.0。

- 除法 (/) ：结果永远是浮点数，即使两个整数相除能整除，结果也会带上小数位（如 4 / 2 得 2.0）。

- 整除 (//) ：取整数部分，常用于取整操作。

- 取余 (%) ：返回余数，最常见的用途是判断奇偶：num % 2 == 0 表示偶数，否则为奇数。

## 2.2 逻辑运算符

逻辑运算符用于组合多个条件，返回布尔值 `True` 或 `False`。

- `and` (与) ：两边都为真才为真
- `or` (或) ：至少一边为真即为真
- `not` (非) ：取反

```python
x = 5
print(x > 3 and x < 10)   # True
print(x > 10 or x < 3)    # False
print(not (x == 5))       # False
```

逻辑运算在条件判断中非常常用，比如在 `if` 或 `while` 中组合多个判断条件。

**聊聊布尔值本身**。

在 Python 中，`True` 和 `False` 其实是关键字，但它们底层对应的就是整数 `1` 和 `0`：

```python
print(int(True))   # 输出 1
print(int(False))  # 输出 0
```

这意味着任何需要布尔值的地方，你都可以直接用数字来代替：**非零的数字被视为 `True`，`0` 被视为 `False`**。

```python
if 1:               # 等价于 if True
    print("成立")   # 永远会执行

if 0:               # 等价于 if False
    print("不成立") # 永远不会执行
```

这也解释了一个在 Python 中看似“奇怪”但非常经典的永动机写法：

```python
while 1:   # 1 永远为真，等价于 while True
    print("循环中")   # 会无限循环下去
```

这里的 `while 1` 会一直循环，因为 `1` 永远被当作 `True` 处理。这种写法在老代码中很常见，本质上就是 `while True` 的简写。所以当你看到 `while 1` 时，只需要知道：**只要数字不是 0，条件就永远为真**。

# 3. 代码打包 (函数与类)

当代码越来越多，我们需要**打包**起来复用，避免重复书写。

## 3.1 函数 (function)

简单来说，函数就是**打包了一套数据处理流程**。你不用关心它内部是怎么一步步处理的，只需要知道“给它什么，它会返回什么”就够了。这种把一段逻辑封装成一个独立单元、按流程执行的方式，通常被称为**面向过程编程**。

```python
# 定义函数
def greet(name):
    return f"你好，{name}！"

# 调用函数
message = greet("小明")
print(message)   # 输出：你好，小明！
```

我们拆开来看这段代码做了什么。

**定义函数**：用 `def` 关键字告诉 Python“我要定义一个函数”，后面跟函数名（这里叫 `greet`），括号里写参数（这里叫 `name`），冒号后面缩进的部分是函数体。函数体里用 `return` 返回结果。

**调用函数**：写 `greet("小明")` 时，Python 会跳进函数体，把 `"小明"` 赋给参数 `name`，执行完 `return` 后把结果返回给调用处，赋值给 `message`。

**函数的好处**：如果你需要多次对不同的名字做同样的操作，不用重复写代码，只需要反复调用同一个函数即可：

```python
print(greet("小明"))   # 你好，小明！
print(greet("小红"))   # 你好，小红！
print(greet("小刚"))   # 你好，小刚！
```

> **关于“面向过程”的简单理解**：
>
> 面向过程的核心理念是：程序就是一系列操作步骤的集合，把数据丢进去，经过一步步处理，最后输出结果。函数就是用来组织这些步骤的基本单元。你写函数 A 处理第一步，函数 B 处理第二步，然后按顺序把它们串起来，整个程序就按照你设计的流程跑完了。初学阶段你大部分时间都在写这种风格的代码，它直观、好理解，非常适合从零开始建立编程思维。


## 3.2 类 (class)

如果说函数是把一段逻辑打包成一个可调用的名字，那么类就是把**数据**和**操作这些数据的函数**打包在一起。类里面定义的函数不叫函数，叫**方法**；类里面存储的数据不叫变量，叫**属性**。

由于类将操作对象 (数据) 和操作方法 (操作这些数据的函数) 捆绑在一起，这意味着类的设计是围绕着操作对象而展开的。这种打包方式，被称为**面向对象编程**。

初学者可以先了解概念，后续再深入。我们先看一个例子：

```python
class Dog:
    def __init__(self, name):   # 初始化方法
        self.name = name

    def bark(self):
        print(f"{self.name} 在汪汪叫！")

my_dog = Dog("旺财")
my_dog.bark()   # 输出：旺财 在汪汪叫！
```

我们拆开来看这段代码做了什么。

**第一步：定义类**

```python
class Dog:
```

`class` 是关键字，表示“我要定义一个类”，`Dog` 是类名，约定首字母大写。

**第二步：写初始化方法**

```python
def __init__(self, name):
    self.name = name
```

`__init__` 是一个特殊的方法名（前后各两个下划线），它的作用是在你创建对象时**自动执行**。你不需要手动调用它，写 `Dog("旺财")` 的时候，Python 会自动把 `"旺财"` 传给 `name` 参数，然后执行 `__init__` 里的代码。

这里的 `self` 代表“**这个对象自己**”，也就是将来创建出来的具体那只狗。`self.name = name` 的意思是：把传入的 `name` 存到这个对象的 `name` 属性里，以后可以通过 `self.name` 来访问它。

**第三步：写一个普通方法**

```python
def bark(self):
    print(f"{self.name} 在汪汪叫！")
```

`bark` 是咱们自定义的方法，它接收 `self` 作为第一个参数（表示“这个对象自己”），然后用 `self.name` 拿到了之前存好的名字。

**第四步：用类创建对象（也叫“实例化”）**

```python
my_dog = Dog("旺财")
```

这句代码做了三件事：
1. 创建一个新的空对象；
2. 自动调用 `__init__` 方法，把 `"旺财"` 传进去，存到 `self.name` 里；
3. 把创建好的对象赋值给变量 `my_dog`。

现在 `my_dog` 就是一只名字叫“旺财”的具体狗了。

**第五步：调用对象的方法**

```python
my_dog.bark()
```

这句代码的含义是：调用 `my_dog` 这个对象的 `bark` 方法。执行时，Python 会自动把 `my_dog` 作为 `self` 传进去，所以 `bark` 里的 `self.name` 拿到的就是 `"旺财"`，最终输出“旺财 在汪汪叫！”。

**类比理解**：

类就像是**一张狗的设计图纸**，规定了狗有名字、会叫。而 `my_dog = Dog("旺财")` 就是按照这张图纸造出了一只**真的狗**。你可以用同一张图纸造出很多只狗：

```python
dog1 = Dog("旺财")
dog2 = Dog("小黑")
dog1.bark()   # 旺财 在汪汪叫！
dog2.bark()   # 小黑 在汪汪叫！
```

每只狗都有自己的名字，互不干扰。

> **现阶段只需记住**：类是用来创建对象的模板，对象拥有自己的属性和行为。你用同一个类可以创建多个互不干扰的对象，每个对象都有自己的数据。后面的编程中你会越来越习惯这种组织代码的方式。

# 4. 文件操作

## 4.1 文件的调用 (打开、读取、写入)

使用函数 `open()` 可以打开一个文件，它的第一个参数是文件路径，第二个参数是打开模式：

- `'r'` (read) ：读取模式，文件必须已经存在，否则报错。
- `'w'` (write) ：写入模式，文件不存在则自动创建，**存在则会清空原有内容**，相当于覆盖重写。
- `'a'` (append) ：追加模式，文件不存在则自动创建，写入的内容会添加到**文件末尾**，原有内容不会被覆盖。

此外，当文件包含中文时，建议指定 `encoding="utf-8"`，否则在不同系统上可能出现乱码。

```python
# 写入文件
file = open("test.txt", "w", encoding="utf-8")  # 打开文件 (不存在则创建)
file.write("Hello, Python!")                    # 写入内容
file.close()                                    # 关闭文件，释放资源

# 读取文件
file = open("test.txt", "r", encoding="utf-8")  # 打开已有文件
content = file.read()                           # 读取全部内容
print(content)                                  # 输出：Hello, Python!
file.close()                                    # 读取完成后也要关闭
```

需要留意的是，如果以 `'w'` 模式打开一个已有文件，它里面的旧内容会被**清空**。如果你只是想追加内容而不是覆盖，应该使用 `'a'` 模式。手动调用 `close()` 是为了告诉操作系统“这个文件我不用了”，释放它占用的资源。如果忘记调用，程序结束时系统虽然会自动回收，但在程序运行期间，文件可能一直被占用，导致其他程序无法操作它。

## 4.2 Python 的自动关闭特性 (with 语句)

手动调用 `close()` 的隐患不只是“容易忘”。即使你记得调用，如果程序在到达 `close()` 之前抛出了异常，这一行仍然可能被跳过。此外，笔者曾遇见过打开一个文件并长时间保持打开状态，却在两次写入之间耗时过久时，这个文件“失效”的情况。等程序继续写入时，文件早已“不可用”，只留下一句报错。目前尚不清楚导致这种 bug 的确切原因是什么。

这正是 Python 社区普遍推荐 `with` 上下文管理器的原因。它能在代码块结束时**主动、确定地**执行 `close()`，即使发生异常退出，也能保证文件被关闭。基本用法如下：

```python
# 写入 (自动关闭)
with open("test.txt", "w", encoding="utf-8") as f:
    f.write("自动关闭，放心！")

# 读取 (自动关闭)
with open("test.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)
```

但有一点需要澄清：**`with` 不能保证在代码块执行中途文件一定安然无恙。** `sleep()` 是 `time` 模块中用于让程序暂停的函数，我们用 `sleep()` 来模拟打开文件后的长时间耗时操作：

```python
from time import sleep # 调用 sleep 包

with open("data.txt", "w") as f:
    sleep(times)    # 假设 times 很长
    f.write('Hello World!')
```

在上面这种写法中，文件虽然是用 `with` 打开的，但在 `sleep()` 期间文件一直处于打开状态。如果这段时间足够长，且恰好触发了某些未知的边界条件 (比如笔者此前遇到过的情形)，文件就可能意外“失效”，最终在写入时抛出错误。

**更稳妥的做法不是把 `with` 当作一个“大包”，而是利用它来做“小包”：**

```python
sleep(times)    # 假设 times 很长
with open("data.txt", "w") as f:
    f.write('Hello World!')
```

这个写法的关键区别在于：文件只在写入的那几毫秒内打开，写完立即自动关闭。其他操作耗时再长，文件都没有被打开，自然不存在“文件一直开着”的问题。

换句话说，`with` 的真正价值不是“用更大的包把代码罩住”，而是“精确控制文件的打开时间”——需要时打开，用完立即关闭，绝不让文件一直开着。这才是 `with` 在实战中最稳妥的用法。

# 5. 代码规范性

写出能运行的代码只是第一步，写出**好看、易读**的代码同样重要。

## 5.1 缩进 (Indentation)

Python 用**缩进**表示代码块层级，不像其他语言用大括号。缩进必须**一致** (一般用 4 个空格)。

```python
# 正确缩进
if True:
    print("缩进 4 空格")
    print("同一层级")

# 错误示范 (缩进不一致会报错) 
# if True:
#   print("用了2空格")
#     print("又用了4空格")   # IndentationError
```

> 大多数代码编辑器会自动将 Tab 转为空格，建议设置 Tab = 4 空格。

## 5.2 注释 (Comment)

注释是给**人**看的解释，Python 解释器会完全忽略它，不会影响程序的运行。

- **单行注释**：以 `#` 开头，用于解释单行代码或做简短说明。
- **多行注释**：用三个引号 `'''` 或 `"""` 包裹，通常放在文件开头、函数或类的开头，用于写较长的说明。

```python
# 这是单行注释，解释下面这行代码的作用
age = 18

"""
这是多行注释
可以写较长的说明文字
比如说明整个模块的用途
"""
```

**注释应该写什么？**

很多新手容易犯的毛病是注释“代码在做什么”，比如 `i += 1  # i 加 1`，这种注释毫无意义——代码本身已经说清楚了。好的注释应该解释**为什么这么做**，也就是代码背后的意图和思路。

一个简单而有效的注释习惯是：**记录你的输入、输出和原理**。换句话说，在你写一段逻辑之前，先用注释回答三个问题：

- 这段代码的输入是什么？ (数据从哪里来、是什么格式)
- 这段代码的输出是什么？ (期望得到什么结果)
- 这段代码的核心思路是什么？ (实现逻辑)

```python
# 输入：一个包含多个数字的列表
# 输出：列表中所有偶数的平方组成的新列表
# 原理：遍历列表，筛选偶数后计算平方，收集到新列表中
numbers = [1, 2, 3, 4, 5, 6]
result = []
for n in numbers:
    if n % 2 == 0:
        result.append(n ** 2)
print(result)   # 输出：[4, 16, 36]
```

这样做有几个好处：首先，写注释的过程会让你先把思路理清楚，而不是直接上手写代码然后在过程中把自己绕晕。其次，当代码量增多时，你能快速回想起当初的设计意图，而不需要从头读一遍每一行代码。在调用时也能快速上手。

**函数的注释 (文档字符串)**：

在定义函数时，可以在函数内部开头用三个引号写一段说明，这叫**文档字符串 (docstring)**。它和普通注释的区别在于，文档字符串可以通过 `help()` 函数被查看，方便其他使用者了解函数的用途。

```python
def calculate_average(numbers):
    """
    计算一个数字列表的平均值。

    输入：一个包含数字的列表
    输出：平均值 (浮点数)
    原理：先求和，再除以列表长度
    """
    total = sum(numbers)
    return total / len(numbers)

# 通过 help 查看函数说明
help(calculate_average)
```

在函数中写文档字符串是一个非常好的习惯，它让代码自带“说明书”，别人 (包括未来的你自己) 看这个函数时不需要去猜它是干嘛的。

**最后一点**：不必过度注释。好的代码本身应该是清晰、易读的，变量名取得好、逻辑分得清，很多地方根本不需要注释。把注释留给那些**确实需要解释的复杂逻辑**，它才能真正发挥价值。

Python 的一大魅力在于**海量的第三方库**。你不需要自己重新发明轮子，只需安装并导入别人写好的库，就能快速实现复杂功能。

```python
import requests

print(response.status_code)   # 输出 200
```

常用库举例：
- **`pandas`**：数据处理
- **`numpy`**：科学计算
- **`matplotlib`**：绘图
- **`flask`** / **`django`**：Web 开发

初学时，**先学会阅读库的官方文档**，知道怎么调用函数、传递参数，比背下所有方法更重要。

## 6.2 调用你自己写的代码

除了调用别人写的库，你还需要学会调用**自己写的代码**——比如你在一个文件里写好了几个常用函数，想在另一个文件里直接使用，而不需要复制粘贴。

假设你写了一个 `my_tools.py` 文件，里面放了一个函数：

```python
# my_tools.py
def greet(name):
    return f"你好，{name}！"
```

现在你在另一个文件 (比如 `main.py`) 里想用这个函数，只需要用 `import` 导入它：

```python
# main.py
import my_tools

message = my_tools.greet("小明")
print(message)   # 输出：你好，小明！
```

如果不想每次写 `my_tools.` 前缀，也可以用 `from ... import ...` 直接把函数“拎”出来：

```python
# main.py
from my_tools import greet

message = greet("小明")   # 直接调用，不需要前缀
print(message)   # 输出：你好，小明！
```

**注意几点**：

- 两个文件需要在**同一个文件夹**下，否则 Python 找不到。
- 导入时**不需要加 `.py` 后缀**，写 `import my_tools` 而不是 `import my_tools.py`。
- 文件名建议用纯英文，不要以数字开头（比如 `1_tools.py` 就不行）。

把自己写的代码拆成多个文件，是组织大型项目的常用方式。好处很明显：通用功能放一起，主逻辑放另一个文件，各司其职，方便维护和复用。

# 7. print 调试法 (最简单的调试手段)

当程序运行结果与预期不符时，最直接的排查手段是在**关键位置插入 print()** 语句，包括：
  - 打印出关键变量的值，以便对照实际执行结果与预期是否一致。
  - 在程序分支的关键节点 (如条件判断处、循环进入/退出处) 插入 print()，用以跟踪程序的执行轨迹。

```python
def divide(a, b):
    print(f"a={a}, b={b}")   # 调试：看传入的参数
    result = a / b
    print(f"result={result}") # 调试：看计算结果
    return result

divide(10, 0)   # 你会看到 b=0，然后报错 ZeroDivisionError
```

通过打印信息，你可以快速定位哪一步出了问题。虽然还有更高级的调试工具 (如 pdb、IDE 断点)，但对于入门者，`print` 足够应对 80% 的场景。
