Pandas 思考题：从 API 使用者到开发者

很多初学者看完教程后会产生一种错觉 (包括曾经的我) ：教程里的代码我都跑通了，参数我也都认识了，我应该算“会 Pandas”了吧？

然后一遇到报错就懵了。

原因很简单：教程教的是“在正确路径上怎么走”，但真实世界里的代码，从来不会一路绿灯。

这篇博客不是教程，是教程的“镜像世界”。在这里，我会刻意制造一些教程里不会出现的场景——参数冲突、列数对不齐、现成函数被禁用。你需要用已有的知识，在一条不那么平坦的路上把代码跑通。

建议先完成 Python 入门：写给完全没学过编程的你 和 Pandas 简明教程 教程的学习后再做本套题。此外，直接看答案将极大削弱训练效果。

说明：本套题共 6 道，难度由浅入深。前两题侧重“排错”与“基础操作”，中间两题侧重“替代方案”与“原理辨析”，最后两题侧重“从零实现”。建议每道题都先自己写一遍，哪怕写得很“笨”也没关系。

第 1 题 (基础排查与异常定位)

已知 iris 数据集实际只包含 5 列数据 (萼片长、萼片宽、花瓣长、花瓣宽、品种) 。如下方代码所示，该数据已被保存为 制表符分隔 (.tsv) 的文件。

要求：请找出下列代码中的错误代码，并指明报错的具体原因。

第 2 题 (字符串向量化操作)

将鸢尾花数据集 (iris) 中 species 列的每个字符串元素内的所有字母 's' (区分大小写) 替换为下划线 '_'。请写出实现代码，并注意保持原数据结构不变 (或返回新副本) 。

第 3 题 (非算术方式的列广播)

现有一个包含多列数值型数据的 DataFrame。请编写一段代码，为该 DataFrame 的所有数值列同时加上一个固定常数 (如 c = 3.14) 。

限制条件：严禁使用 df + c、df.add(c)、df.applymap(lambda x: x+c) 等直接算术运算。

第 4 题 (函数位置参数顺序的影响辨析)

在调用 pandas 函数时，位置参数的传入顺序是否一定会影响最终的运算结果？请以 pd.read_csv 中 usecols (传入整数索引列表 vs 传入列名字符串列表) 与 names 参数的配合使用为例，或自选其他合适的函数 (如 pd.DataFrame.drop 中的 labels 与 axis) ，给出您的结论并详细阐述理由。

第 5 题 (模拟纵向合并 – 堆叠行)

在不使用 pd.concat() 函数的前提下，实现两个 DataFrame 的纵向 (按行) 合并功能。请写出核心实现代码，并简要说明您是如何达成行堆叠效果的。

第 6 题 (模拟横向合并 – 连接列)

在不使用 pd.merge() 函数的前提下，实现两个 DataFrame 的横向 (按列) 合并功能。要求根据两个 DataFrame 的行索引进行对齐连接。请写出实现代码，并详细解释您的底层实现逻辑 (例如如何处理索引对齐、如何处理重复列名等) 。

写在最后

这 6 道题如果做得很顺利，说明你对 Pandas 的理解已经超越了“记住 API”的层面，开始进入“理解设计逻辑”的阶段。

如果做得不顺利 (尤其是第 5、6 题) ，这恰恰是好事。真正的成长往往发生在“感觉手里工具不够用”的时刻。 那些教程没教你的报错场景、那些被禁用的现成函数、那些需要你自己造轮子的瞬间——这些才是把一个“会用工具的人”变成“能创造工具的人”的关键台阶。

做完之后，欢迎对照参考答案复盘 (后续发布，敬请期待) 。但请记住：参考答案展示的只是一种可行的路径，你自己的解法只要逻辑正确、能跑通，就是好解法。哪怕写得再“笨”，那也是你独立走通的路。

祝你写代码的时候，能感受到一点点“解谜”的乐趣。

— Aurora Hiker
